# C 盘安全清理工具 (Safe C: Drive Cleaner) · 增强版

一套用于扫描并**安全**清理 C 盘临时文件、回收站、系统缓存，以及**常用软件产生的应用缓存**的可执行工具；
并集成了**大文件扫描、内存与后台进程监控、定时自动清理、图表化对比报告**等实用能力。
删除前展示完整清单与预估释放空间，须用户明确确认后方可执行；内置多重保护机制，杜绝误删系统关键目录与误杀关键进程。

## 功能总览

| 模块 | 能力 | 安全边界 |
|------|------|----------|
| 磁盘清理 | 白名单临时/缓存 + 39 类应用缓存，勾选后一键清理 | 仅是白名单目录内的文件，删除前逐路径二次越界校验 |
| 大文件扫描 | 按阈值找出用户目录中的大文件，定位/打开/送回收站 | 系统目录与可执行/驱动类文件禁止删除；删除走回收站可还原 |
| 内存与进程 | 实时内存/磁盘曲线、后台进程占用排行、结束驻留进程 | 系统关键进程硬编码保护并隐藏；结束前二次确认 |
| 自动清理 | 定时规则写回配置 + 注册 Windows 计划任务 + 静默执行 | 与手动清理同一套白名单与越界校验 |
| 排除设置 | 图形化维护保留路径/模式/文件年龄 | 只能「收窄」清理范围，不能放宽删除边界 |
| 报告 | 清理前后对比，TXT + HTML（含柱状图） | 只记录数据，不参与删除决策 |

### 图形界面版（exe）

双击 `dist\CleanCDrive.exe`，界面分为 5 个标签页：

**① 磁盘清理** —— 自动扫描并列出所有可清理项（**分类 · 文件数 · 预估大小**），
**每一项一个勾选框**，自行勾选 → 点「一键清理」→ 确认后执行 → 弹出前后对比报告；
右侧另有「占用排行 TOP 8」条形图，快速看出谁最占空间。

**② 大文件扫描** —— 设定阈值（默认 200MB）后扫描用户目录，结果按大小倒序排列，
支持**双击定位**、打开文件、以及**送回收站**（可还原）。系统目录与 `.exe/.dll/.sys` 等
可执行/驱动类文件被硬性拦截，不会出现在可删除范围。

**③ 内存与进程** —— 顶部为**实时曲线**（每秒采样，内存使用率 + C: 可用空间双线），
下方是**后台进程内存占用排行**；系统关键进程（`csrss`/`lsass`/`svchost`/`winlogon` 等）
已被保护并**不会出现在列表中**，可安全关闭的常见驻留程序会标注「可安全关闭」，
支持多选后一键结束（结束前弹出确认并列出 PID 与进程名）。

**④ 自动清理** —— 设定频率（每日/每周/每小时/每次登录）、时间与目标（系统临时/应用缓存/回收站），
点「保存并注册计划任务」后由 Windows 计划任务在后台静默执行；
也可「立即执行一次」「查看任务状态」「取消计划任务」。

**⑤ 排除设置** —— 图形化增删「保留路径」「保留文件名模式」与「文件年龄阈值」，
保存后自动写回 `cleanup_config.ini`，任何清理动作都会跳过命中项。

- 受保护的系统关键目录在界面上明确列出（灰显、不可勾选）。
- 主界面采用 tkinter（Python 标准库），exe 完全自包含，目标机器**无需安装 Python**。
- 配置：把 `cleanup_config.ini` 放到 exe 同目录即可生效（未放则使用内置默认值）。

## 快速使用（命令行版）

1. 双击 `CleanCDrive.bat`（或命令行 `powershell -File CleanCDrive.ps1`）。
2. 程序先**扫描**并列出：
   - 受保护的系统关键目录（仅展示，绝不会删除）；
   - 可安全清理的白名单扫描根；
   - 每个分类的文件数、预估大小、合计可释放空间；
   - 清理前 C: 盘可用空间。
3. 提示 `请输入 YES（全大写）以确认执行删除`。只有输入 `YES` 才会删除，其他任意输入均取消。
4. 删除完成后输出：清理前后可用空间对比、实际释放总量、分类明细，并保存为 `cleanup_report_*.log`。

### 常用参数

```bat
CleanCDrive.bat                 :: 交互式：预览 + 确认后删除（含系统临时 + 应用缓存）
CleanCDrive.ps1 -DryRun         :: 仅预览，不删除（推荐先跑一次看清单）
CleanCDrive.ps1 -SkipRecycleBin :: 不处理回收站
CleanCDrive.ps1 -SkipAppCache   :: 跳过应用缓存，只清理系统临时/回收站
CleanCDrive.ps1 -AppCacheOnly   :: 仅扫描并清理应用缓存（跳过系统临时目录）
CleanCDrive.ps1 -ConfigPath "D:\my.ini"  :: 使用自定义配置
```

## 安全机制（核心）

1. **白名单扫描根**：只有明确列出的临时/缓存目录中的文件才会被收集与删除，例如
   `%TEMP%`、`C:\Windows\Temp`、`C:\Windows\SoftwareDistribution\Download`、
   `C:\Windows\Prefetch`、IE/Edge 缓存、缩略图缓存目录等。
2. **结构性越界防护**：删除阶段对每个待删文件做二次校验，确认其完整路径位于某个安全根内；
   任何解析后落到白名单之外的路径都会被拒绝（即使配置文件被恶意篡改也无法删除系统目录）。
3. **受保护目录标注**：`C:\Windows`、`C:\Program Files`、`C:\Users`、`C:\ProgramData`、
   `C:\$Recycle.Bin`、`C:\System Volume Information` 等仅用于展示，绝不被遍历或删除。
4. **明确确认门**：必须输入全大写 `YES` 才执行删除，杜绝误触。
5. **保留规则**：通过 `cleanup_config.ini` 指定需保留的路径/模式/文件年龄，被命中者扫描阶段即跳过。
6. **只读安全失败**：文件被占用（锁定）导致删除失败时，仅计入「失败」并跳过，不会中断或报错退出。
7. **空目录清理**：仅移除安全根内、删除文件后变为空的子目录，且删除前再次校验其父目录在白名单内。
8. **关键进程保护**：`System`/`csrss`/`lsass`/`winlogon`/`svchost`/`services`/`explorer` 等
   核心进程硬编码进保护名单，界面**不显示**，任何结束请求都会被拒绝。
9. **大文件删除走回收站**：大文件一律通过 `SHFileOperation` 送入回收站（可还原），
   不做永久删除；系统目录前缀与可执行/驱动类扩展名被硬性拦截。
10. **所有危险动作二次确认**：清理、结束进程、送回收站均先弹出确认框并列出完整清单。

## 应用缓存清理（新增功能）

自动识别常用软件产生的无用缓存、日志、更新残留，避免 C 盘因缓存堆积爆满。

- **识别的软件/缓存**（白名单，仅清理列出的具体缓存子目录）：
  - 浏览器：Chrome / Edge / Firefox / Brave / Opera 的 `Cache`、`Code Cache`、`GPUCache` 等；
  - 即时通讯：Discord、Slack（缓存+日志）、Teams（缓存+代码缓存+临时+日志）、Telegram、WhatsApp、**微信**、QQ；
  - 开发工具：npm / pip / Yarn 缓存、JetBrains 日志；
  - 媒体/游戏：Spotify、Steam（下载残留+应用缓存）、NVIDIA 着色器缓存、Adobe 媒体缓存；
  - 系统：传递优化缓存（Delivery Optimization）。
- **安全判定**：每个缓存项只清理「明确的缓存子目录」（如 `...\Cache`、`...\logs`），绝不直接指向软件主目录；日志类目录仅删 `*.log/*.txt/*.old`，缓存目录删其内部全部文件。
- **排除项配置**（`cleanup_config.ini` 的 `[AppCache]` 段）：
  - `Enable=0` 关闭整个功能；
  - `ExcludeApp=软件名` 排除某软件（如 `微信 缓存`）；
  - `ExcludePath=完整路径` 排除某个缓存目录；
  - `ExcludePattern=*.db` 排除特定文件类型（即使位于缓存目录也不删）。
- 仍受全套安全机制约束（白名单、结构性越界校验、确认门）。

## 大文件扫描（新增功能）

用于解决「C 盘莫名被占满」中最常见的一类原因——少数几个超大文件。

- **扫描范围**：`%USERPROFILE%` 与 `C:\Users\Public`；自动跳过 `Temp`、`INetCache`、
  `Packages`、`OneDrive`、`$Recycle.Bin` 等噪音目录与所有符号链接 / 目录联接，避免死循环。
- **筛选**：默认阈值 200MB（界面可改，配置文件 `[LargeFiles] ThresholdMB`），
  结果按大小倒序，最多显示 `MaxItems` 条。
- **可执行动作**：双击或「定位文件」在资源管理器中选中、「打开文件」、「送回收站」（批量、可还原）。
- **强制保护**：位于 `C:\Windows`、`Program Files`、`ProgramData` 等系统目录前缀下的文件，
  以及 `.exe/.dll/.sys/.msi/.ocx/...` 等可执行/驱动类文件，删除请求会被拦截并明确提示。
- **预期效果**：安装包残留、镜像、录屏、游戏安装缓存等「一次性大文件」可被快速定位与安全回收。

## 内存与后台进程（新增功能）

解决「内存被后台程序悄悄吃满、机器越来越卡」的问题。

- **实时曲线**：每秒采样，绘制内存使用率（科技蓝面积+折线）与 C: 盘可用空间（青色虚线，归一化）60 秒滚动窗口，带图例与网格。
- **占用排行**：列出进程名、内存占用与窗口标题，按内存降序，最多 150 条。
- **可安全关闭提示**：内置常见驻留程序名单（Edge/Chrome、微信/QQ/钉钉、Node/Python/VS Code、
  Steam/Spotify、Adobe 系列等），命中者在列表中标注「可安全关闭」。
- **关键进程保护**：`System`/`csrss`/`wininit`/`winlogon`/`services`/`lsass`/`svchost`/
  `dwm`/`explorer`/`MsMpEng` 等约 40 个核心进程既**不显示**也**不可结束**；结束动作前弹出确认框。
- **预期效果**：一眼看出谁最占内存，安全释放被挂起程序占用的内存，缓解卡顿。

## 自动清理与定时任务（新增功能）

- **规则项**：频率（每日 / 每周日 / 每小时 / 每次登录）、时间、目标（系统临时 / 应用缓存 / 回收站）。
- **实现方式**：通过 PowerShell 计划任务模块（`Register-ScheduledTask`）注册名为
  `CleanCDrive_AutoClean` 的任务，调用 `CleanCDrive.exe --autorun` 静默执行；
  不依赖 `schtasks.exe`，兼容性更好。
- **静默模式行为**：读取 `cleanup_config.ini` 的 `[AutoClean]` 配置 → 按同一套白名单扫描 →
  执行删除（含结构性越界校验）→ 生成 `autorun_report_*.log` 与 `.html` 报告。
- **手动触发**：界面「立即执行一次」，或命令行 `CleanCDrive.exe --autorun`。
- **预期效果**：日常无需人工干预，磁盘占用保持在低位；若提示权限不足，以管理员身份运行本程序即可。

## 报告与可视化（增强）

- **TXT 报告**：`cleanup_report_*.log`，含清理前后可用空间、实际释放量、分类明细（只列真实删除项）、跳过原因。
- **HTML 报告**：新增 `cleanup_report_*.html`，含 4 个 KPI 卡片（清理前后可用空间、实际变化、删除字节合计）、
  **分类明细柱状图**与明细表，可在「清理完成」对话框一键打开。
- **占用排行图**：磁盘清理页右侧的 TOP 8 条形图，直观呈现主要占用来源。
- 报告默认保存在 exe 同目录，点击「打开报告目录」即可定位。

## 配置文件示例 (cleanup_config.ini)

```ini
[Retain]
; 保留某目录（含其全部内容）
; Path=%LOCALAPPDATA%\Temp\KeepMe
; 按文件名模式保留
; Pattern=*.log
; Pattern=important*.tmp

[SafeRoots]
; 追加可安全清理的缓存目录
; Add=C:\MyApp\Cache
; 关闭某个默认安全根
; Exclude=C:\Windows\Prefetch

[Options]
; 仅删超过 N 天未修改的文件；0 = 不限制
RetainFileAgeDays=0

[AppCache]
Enable=1
; ExcludeApp=微信 缓存
; ExcludePath=%LOCALAPPDATA%\Google\Chrome\User Data\Default\Cache
; ExcludePattern=*.db

[LargeFiles]
ThresholdMB=200
MaxItems=200

[AutoClean]
Enable=0
Schedule=DAILY
Time=03:00
Targets=system,appcache
IgnoreBattery=0
```

> 注意：配置文件只能「收窄」清理范围（保留更多 / 少扫一些），不能把系统目录加入删除目标。
> 界面「排除设置」与「自动清理」页保存的规则会写入带标记的托管区块，可安全与手工配置共存。

## 命令行参数（exe 版同样支持）

```bat
CleanCDrive.exe                  :: 打开图形界面（默认）
CleanCDrive.exe --selftest       :: 自检：扫描/内存/进程/报告模块全量验证，结果写入 _selftest.txt
CleanCDrive.exe --guitest        :: 界面冒烟测试：完整构建界面并跑 35 项断言，结果写入 _guitest.txt
CleanCDrive.exe --autorun        :: 静默自动清理（供计划任务调用）
```

> `--guitest` 会将窗口以全透明方式离屏渲染（布局尺寸真实、不闪屏），
> 依次验证主题令牌、导航切换、扫描结果、勾选联动、图表绘制、进程表、样式套用等，
> 全通过输出 `GUI_OK`；有任何失败会逐条列出并给出 `GUI_ISSUES: N`。
>
> 其中包含 4 条**布局回归断言**，它们各自对应一个真实踩过的缺陷：
>
> | 断言 | 防止的回归 |
> |------|-----------|
> | 各标签页内容不超出可视高度 | 页面内容纵向溢出，底部操作行与状态栏被挤出窗口 |
> | 非弹性控件均未被压扁（实际高度 ≥ 请求高度） | pack 顺序错误导致按钮/输入行只剩半高，文字被裁掉 |
> | Canvas 文字不越出画布宽度（长文本已截断） | 长分类名/长路径压到右侧「项数 · 大小」上 |
> | 所有按钮宽度容得下自身文字（w 按字宽换算） | `w=` 被当成像素而非字符数，按钮被压成 7~18px |
>
> 排查界面问题时，设置 `CCD_LAYOUT_DUMP=1` 再跑 `--guitest`，会把关键控件的实时几何
> 写入 `_layout.txt`（含窗口客户区尺寸、各页子块高度、列表/画布宽度、药丸导航的屏幕坐标）——
> 靠肉眼估算像素远不如直接读数值可靠。

### 窗口尺寸与布局约定

- **窗口自适应屏幕**：设计基准 `1040x840`，实际取 `min(基准, 屏幕可视区)`，
  保证底部操作区在任何分辨率下都不被屏幕下边缘裁掉（1366x768 / 1536x864 是笔记本常态）。
- **底部优先 pack**：页面内的固定操作行一律 `pack(side="bottom")` 并**先于**弹性内容区调用。
  packer 按调用顺序分配空间，后登记的控件在空间不足时会被削减 —— 这是本项目两次
  「按钮被压扁」的根因。
- **弹性区最后 pack**：列表 / 表格 / 日志等可伸缩控件用 `pack(fill="both", expand=True)`
  并放在最后，让它只吃剩余空间。
- **启动页可指定**：设置环境变量 `CCD_START_TAB=0..4` 可让程序直接打开指定标签页，
  供截图与自动化流程使用（Tk 不响应进程内注入的鼠标消息，模拟点击在无交互会话里不可靠）。

## 重新打包 exe

图形界面版由 `CleanCDrive.py`（Python 3 + tkinter，**零第三方 GUI 依赖**）打包而成。
如需自行重新打包：

- **方式一（推荐）**：双击 `build_exe.bat`，自动安装 PyInstaller 并生成 `dist\CleanCDrive.exe`。
- **方式二（手动）**：
  ```bat
  python -m pip install pyinstaller
  python -m PyInstaller --onefile --windowed --name CleanCDrive --add-data "cleanup_config.ini;." CleanCDrive.py
  ```

生成的 exe 仍受上述全部安全机制约束。

> 说明：GUI 版选用 Python + tkinter，因为 tkinter 属 Python 标准库，无需任何第三方 GUI 依赖；
> 打包后的 exe 体积小（约 10 MB）、启动快、完全自包含（目标机器无需安装 Python）。

## 变更记录

### 界面布局修复 + 发布物料

**修掉的布局缺陷：**

1. **原生 Notebook 标签条未真正移除** —— `ttk.Style().layout("TNotebook", ...)` 在当前 clam 主题下
   不可靠，内容区顶部仍留着一排 5 个灰色空标签、白占约 30px 纵向空间。
   改为自绘 `TabStack`（`place` 叠放 + `tkraise` 切换），彻底摆脱原生控件。
2. **底部操作区被压扁** —— 磁盘清理页的「全选 / 一键清理」、大文件页的操作行、
   排除设置页的「保存到配置文件」都放在最后 `pack`，空间不足时被上方弹性内容区削到半高，
   按钮文字被裁掉。全部改为 `pack(side="bottom")` 并提前登记。
3. **排除设置页输入行只露半行** —— Listbox 的请求高度很大，放在它之后 `pack` 的输入框行被挤压。
   改为输入行先 `pack(side="bottom")`。
4. **长分类名压到右侧数字上** —— `%LOCALAPPDATA%\Microsoft\Windows\NetCache` 这类长名会覆盖
   「项数 · 大小」。新增 `_ellipsize()` 按像素宽度截断并补 `…`，右侧列预留固定宽度。
5. **列表右侧 194px 死区** —— `canvas.create_window` 未指定宽度时用窗口「请求宽度」（控件默认 378px），
   行只占画布左侧 2/3。改为在 `<Configure>` 里把内层 Frame 宽度同步为画布宽度。
6. **按钮宽度被当成像素** —— `mk_btn(w=13)` 中 `w` 的语义是字符数，却被直接当像素宽度传给 Canvas，
   按钮实际只有 7~18px 宽、文字全被压扁。改为按字宽换算最小宽度。
7. **窗口高度超出屏幕** —— 硬编码 `1040x840` 在 1536x864 / 1366x768 上会让底部被屏幕裁掉，
   改为按屏幕可视区自适应。

**新增：**

- 4 条布局回归断言（见 `--guitest` 一节），逐条对应上面的缺陷。
- `CCD_LAYOUT_DUMP=1` 布局几何导出，`CCD_START_TAB=0..4` 启动页定位。
- `docs/images/` 界面截图（含分区标注图）。

### 视觉改版（科技蓝 · 小清新）

- 全界面重构为「科技蓝」设计语言：集中化设计令牌（`THEME` / `SP`）、圆角大卡片、柔和双层投影、药丸按钮与分段导航，样式与间距全局统一。
- 自绘控件体系替换 ttk 默认外观：`RoundedCard`、`StatTile`、`PillTabs`、`CheckRow`、`FreshCheck`、`RoundedField`、`Chip`、`StatPill`。
- 磁盘清理页新增三枚数据贴片（可清理合计 / 回收站 / 已选），列表改为全宽圆角勾选行并显示类型胶囊。
- 信息层级重排：顶栏品牌标 + 双数据胶囊、药丸分段导航、卡片化各标签页、统一状态栏。
- HTML 报告与 GUI 共用同一套色源，同步改为蓝色主题（圆角卡片 + 顶部渐变条 + 浅蓝表头）。

**同时修复的两个既有缺陷：**

1. **自绘控件覆盖了 tkinter 内部属性 `_w`（控件路径）** —— `PillButton` / `StatTile` / `RoundedField` / `PillTabs`
   都把宽度存进 `self._w`，会在控件创建后立刻抛异常，导致**图形界面实际无法启动**。
   已统一改名为 `w_px`；`CheckRow` 占用的 `_name` 同步改为 `row_name`（`_name` 同样归 tkinter 所有）。
2. **进程列表存在竞态** —— 进程枚举线程在 `mainloop` 启动前就通过 `root.after` 回投结果，
   会抛 `main thread is not in main loop` 并使进程列表静默为空。已改为在 `mainloop` 启动后再起线程。

此外，`_install_styles()` 此前定义却从未被调用、`Fresh.*` / `Slim.*` 样式从未套用（表格、滚动条、进度条、下拉框一直用系统默认外观），现已接入。

## 注意事项

- 首次使用建议先以 `-DryRun` 预览清单，确认无误后再正式运行。
- 清理 `%TEMP%` 等目录时，部分正在被程序占用的文件会删除失败（属正常现象）。
- 建议在正式删除前关闭不必要的大型软件，以减少文件占用冲突。
- 本工具不处理注册表、不卸载软件、不移动个人数据，仅清理可逆的临时/缓存文件。
